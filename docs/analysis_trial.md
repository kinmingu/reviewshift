# 항목별 감성 분류 실제 모델 시험

## 목적과 제한

이 시험은 Amazon Reviews 2023 공식 7개 카테고리의 영어 리뷰 원문을 대상으로 구조화
출력, 원문 근거 검증, 실행 안정성과 CPU 처리 시간을 확인한다. 사람 정답이 아직 없으므로
정확도·정밀도·재현율·F1을 주장하지 않는다. 원문 근거가 입력에 존재한다는 검사는 모델의
의미적 판정이 맞다는 증명이 아니다.

전체 5,224건 번역과 전체 분류는 실행하지 않았다. 리뷰 번역은 분류의 선행 조건이 아니며,
분류 입력에는 별점도 넣지 않았다.

## 실행 환경과 모델 선택

- Windows 64-bit, Python 3.12.10
- CPU 12 논리 프로세서, NVIDIA GPU 미검출
- 물리 메모리 약 13.85 GiB
- Ollama `qwen3.5:latest`: Q4, 6.6 GB
- 비교 확인한 기존 모델 `qwen2.5:latest`: Q4, 4.7 GB
- 프롬프트 `absa-prompt-v1`, 분류 체계 `review-taxonomy-v1`

새 모델이나 모델 가중치는 다운로드하지 않았다. 먼저 동일한 소수 리뷰에 기존 두 모델을
시험했고, `qwen2.5`가 일부 응답에서 구조화 형식 오류를 반복한 반면 `qwen3.5`가 원문 근거와
구조화 응답을 더 안정적으로 반환하여 70건 시험 모델로 선택했다. 이 비교는 매우 작은
개발용 표본이므로 일반적인 성능 우위를 뜻하지 않는다.

## 표본

- 고정 난수 규칙: SHA-256 순위 기반의 재현 가능한 선택
- 실제 시험: 카테고리별 10건, 총 70건
- 상품 포함: 14개 상품별 5건
- 별점 포함: 1~5점 각각 14건
- 사람 평가용 블라인드 표본: 상품별 10건, 총 140건
- 70건 시험과 140건 블라인드 평가 표본의 중복: 0건
- 혼합 의견, 부정어, 별점과 본문 불일치 후보는 별도 어려운 사례 파일로 분리

## 결과

실제 `qwen3.5:latest` 실행과 실패 건 1회 재시도 결과는 다음과 같다.

| 항목 | 실제 결과 |
|---|---:|
| 시험 리뷰 | 70건 |
| 최종 성공 | 68건 |
| 최종 실패 | 2건 |
| 정상 빈 라벨 | 3건 |
| 저장 라벨 | 183개 |
| 긍정 / 부정 / 중립 | 68 / 109 / 6개 |
| 원문 근거 불일치 저장 | 0개 |
| 입력 길이 평균 / 범위 | 293.4자 / 16~2,775자 |
| 성공 리뷰 누적 처리 시간 평균 | 63.4초 |
| 중앙값 / p25 / p95 | 44.8초 / 39.0초 / 108.6초 |

처리 시간은 재시도 시간을 포함한다. 가장 긴 성공 건은 누적 499.7초였다. 68개 성공 결과를
다시 실행했을 때 모두 `skipped`로 처리됐고, 실패 2건은 `--retry-failed`가 없으면 모델을 다시
호출하지 않아 멱등성과 명시적 재시도 경계를 확인했다.

실패 이력을 합산하면 원문 근거 검증 오류 11회, JSON 형식 오류 2회, 허용되지 않은 분류 코드
오류 5회였다. 이 횟수는 리뷰 수가 아니라 최초 실행·자동 재시도·명시적 재시도의 호출 오류
횟수다. 최종 실패 2건은 다음과 같다.

- 스포츠 리뷰: 원문의 연속 공백은 안전하게 실제 원문으로 매핑할 수 있었지만, 후속 응답이
  허용되지 않은 `performance/inflation` 코드를 반복해 최종 실패로 남겼다.
- 완구 리뷰: 리뷰에는 없는 상품 정보 `Multicolor`를 원문 근거로 반복해, 가짜 근거를
  수용하지 않고 최종 실패로 남겼다.

카테고리별로 앞의 5개 카테고리는 각 10/10건 성공했고, `Sports_and_Outdoors`와
`Toys_and_Games`는 각각 9/10건 성공했다. 정상 빈 라벨과 실패를 구분해 저장했으며 실패를
불만 0건으로 집계하지 않는다.

## 전체 분류 시간 추정

성공 68건의 CPU 순차 처리 실측을 5,224건에 단순 환산하면 평균 기준 약 92.0시간이다.
p25~p95를 각각 적용한 참고 범위는 56.66~157.61시간이다. 재시도 빈도, 운영 중 다른 CPU
부하, 리뷰 길이 분포에 따라 달라지므로 완료 시간 보장이 아니다. 기존 번역 시험의 13.8시간
추정값은 분류 추정에 사용하지 않았다.

이 결과를 보고하기 전에는 전체 5,224건 배치를 실행하지 않았으며, 전체 실행에는 사용자
확인이 필요하다.

## 결과물

- `data/evaluation/trial_70.json`: 실제 시험 리뷰 ID
- `data/evaluation/trial_70_report.json`: 실행 통계와 단순 전체 처리 시간 추정
- `data/evaluation/trial_70_predictions.csv`: 실제 시험 예측과 원문 근거
- `data/evaluation/human_review_blind_140.csv`: 모델 예측을 숨긴 사람 정답 작성 파일
- `data/evaluation/human_review_predictions_140.csv`: 별도 비교 파일(아직 미실행이면 `not_run`)
- `data/evaluation/hard_cases_check.csv`: 무작위 정확도와 섞지 않는 어려운 사례 점검 파일
- `data/evaluation/sample_manifest.json`: 표본 수와 중복 여부

`data/`는 원자료와 평가 중간 산출물을 포함하므로 Git 추적 대상이 아니다.

## 의미 오류 수정 후 고정 14건 개발 비교

기존 70건 중 의심·실패 사례, 짧고 긴 입력, 혼합 의견을 포함한 14건을
`config/analysis_dev_14.json`에 고정했다. 이 표본은 프롬프트 개발에 사용했으므로 독립 품질
평가가 아니다. 140건 블라인드 사람 평가 집합과 중복은 0건이다.

비교한 설정은 다음과 같다.

- 기준: `amazon-absa-qwen35-v1`, `absa-prompt-v1`
- 개선: `amazon-absa-qwen35-v3`, `absa-prompt-v3`
- 동일 모델: `qwen3.5:latest`, digest
  `6488c96fa5faab64bb65cbd30d4289e20e6130ef535a93ef9a49f42eda893ea7`
- 공통: 영어 원문 전체 사용, 별점 미사용, `temperature=0`, `num_ctx=4096`,
  `num_predict=384`, 사고 모드 끔, CPU 순차 호출
- v3: 상품 메타데이터 제외, 유효한 결합 taxonomy 코드만 허용, 감성 문맥 규칙 추가,
  taxonomy 설명 압축, `keep_alive=30m`, Ollama 세부 시간 저장

초기 v2 탐색 실행은 앞의 6건을 성공한 뒤 2,775자 리뷰에서 9분 이상 응답과 CPU 진행이
멈춰 해당 로컬 프로세스만 종료했다. 성공 6건과 중단 실패 기록은 비활성 run에 보존했다.
최종 비교 집합은 본문을 자른 것이 아니라, 70건 안의 다른 277자 리뷰로 교체해 20~759자
범위의 고정 14건으로 확정했다. 따라서 이 비교는 가장 긴 2,775자 사례의 지연을 대표하지
않으며 전체 시간 추정의 불확실성을 키우는 요인이다.

| 항목 | v1 | v3 |
|---|---:|---:|
| 최종 구조·근거 통과 | 12/14 | 14/14 |
| 최종 실패 | 2 | 0 |
| 성공 건 평균 시간 | 68.50초 | 61.71초 |
| 실패까지 포함한 v1 최종 결과 평균 / v3 평균 | 95.50초 | 61.71초 |
| v3 중앙값 / 범위 | - | 56.66초 / 30.28~143.03초 |
| v3 재시도 | - | 1건 1회 |

v3는 v1 성공 건 평균 대비 약 9.9%, v1의 실패 누적 시간을 포함한 최종 결과 평균 대비 약
35.4% 짧았다. 작은 개발 표본과 당시 시스템 부하에 의존하므로 일반적인 속도 향상을 보장하지
않는다. v1에는 Ollama 세부 메트릭을 저장하지 않아 load·입력·출력 시간을 같은 방식으로
비교할 수 없다. 첫 v2 호출의 cold load는 25.92초였고, 모델을 메모리에 유지한 뒤 v3 최종
성공 응답의 load 평균은 0.009초였다. v3 최종 성공 응답의 입력 처리 평균은 28.26초, 출력
생성 평균은 27.95초였고 DB flush는 0.035초였다. 한 건의 첫 검증 실패 응답 메트릭은 저장하지
못했지만 그 재시도 시간은 리뷰 누적 61.71초 평균에는 포함된다. 모델 서버의 관찰 최대 작업
세트는 약 5.4GB, 전용 메모리는 약 9.7GB였다.

v3의 1차 근거 실패는 759자 리뷰에서 모델이 원문을 생략 부호로 요약한 구간을 인용한
사례였다. 느슨하게 수용하지 않았으며, 제한된 재시도에서 실제 원문 구간을 반환해 성공했다.
출력 제한으로 잘린 응답은 없었고 `done_reason=stop`을 확인했다.

모든 결과가 v1과 달라졌다는 사실은 품질 향상을 뜻하지 않는다. 지정된 두 실패는 없어졌지만
`NO PUMP INCLUDED`를 v3가 `performance.core_performance`로 분류한 결과, `Very harsh paper`를
소재로 분류한 결과 등 의미적으로 의심되는 항목이 남았다. `Low fan...`도 부정 문맥은 제목에
있는데 본문만 근거로 선택했다. 이는 사람 정답 화면에서 확인해야 하며 14/14를 정확도로
표현하지 않는다. 자세한 원문 점검은 `docs/analysis_semantic_audit.md`, 행별 비교는
`data/evaluation/dev14_comparison.csv`에 있다.

14건 실측을 5,224건에 단순 환산한 전체 예상은 평균 약 89.54시간, p25~p95 참고 범위는
52.74~140.32시간이다. 우선 후보 두 달 233건은 평균 약 3.99시간, 같은 범위 환산은
2.35~6.26시간이다. 이미 같은 v3로 성공한 1건은 재사용 가능하고 232건이 새 호출 대상이다.
전체 5,224건과 두 달 233건 배치는 모두 아직 실행하지 않았다.

## 공식 지원 확인

Ollama 공식 문서 기준으로 비스트리밍 응답의 `total_duration`, `load_duration`,
`prompt_eval_count`, `prompt_eval_duration`, `eval_count`, `eval_duration`을 기록했다.
`keep_alive`는 모델을 메모리에 유지하는 공식 요청 옵션이며, 모델이 지원하는 경우 `think=false`로
사고 출력을 끌 수 있다. 로컬 `/api/show`에서 `qwen3.5:latest`의 `thinking` capability를 확인한
뒤 적용했다. 구조화 출력은 `format` JSON schema를 사용했다.
