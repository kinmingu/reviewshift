# 사람 검토 가이드

평가 파일은 Git에서 제외되는 `data/evaluation/`에 저장된다. 원문 리뷰가 포함되므로 외부에
업로드하지 않는다.

## 파일

- `human_review_blind_140.csv`: 상품별 10건, 총 140건의 독립 정답 작성용 파일이다. 모델
  예측이 없어 검토자가 예측에 영향받지 않는다.
- `human_review_predictions_140.csv`: 같은 140건의 모델 비교용 파일이다. 현재
  `prediction_status=not_run`이며 전체 평가 예측 실행 전까지 정확도 계산에 사용하지 않는다.
- `trial_70_predictions.csv`: 카테고리별 10건 실제 모델 시험의 예측·근거·오류·시간 기록이다.
  프롬프트와 파이프라인 점검에 사용했으므로 독립 평가 정확도로 취급하지 않는다.
- `hard_cases_check.csv`: 부정어, 혼합 의견, 배송/제품 구분 가능성이 있는 정성 점검 사례다.
  무작위 140건과 섞어 전체 정확도를 주장하지 않는다.
- `sample_manifest.json`: 표본 분포와 시험·평가 중복 0건을 기록한다.

## 정답 작성 방법

1. API와 Streamlit을 실행하고 `http://127.0.0.1:8501`을 연다.
2. 왼쪽 사이드바에서 `개발·평가 화면`을 켠다.
3. 영어 제목과 본문을 먼저 읽고 평가 항목을 복수 선택한다.
4. 항목별 감성을 선택하고 영어 원문 근거를 그대로 붙여 넣는다. 같은 항목의 긍정·부정을
   동시에 선택할 수 있고, 모호하면 `판단 보류`를 쓴다.
5. 명시적 항목 의견이 없으면 `정상 빈 라벨`을 선택한다. 호출 실패와 같은 뜻이 아니다.
6. 검토자와 메모를 입력해 진행 중으로 저장하거나 완료 저장 후 다음 리뷰로 이동한다.
7. 자동 번역은 필요한 한 건만 요청하고 참고 자료로만 사용한다.
8. 언제든 CSV로 내보내 기존 `gold_labels_json` 형식으로 검토할 수 있다.

진행률과 다음 미완료 위치가 DB에 저장되므로 서버를 다시 실행해도 이어서 검토할 수 있다.
완료 저장 전에는 모델 예측이 숨겨지고, 완료한 뒤에만 별도 비교 영역에 표시된다.

허용 코드는 `docs/analysis_taxonomy.md`와
`config/review_analysis_taxonomy.json`을 따른다. 근거는 영어 원문에 그대로 존재하는 문자열을
복사한다. 별점과 본문이 충돌하면 본문 근거를 판정 기준으로 삼는다.

## 정확도 계산 전 조건

팀원의 실제 정답 입력이 끝나기 전에는 precision, recall, F1 또는 정확도를 계산하지 않는다.
Codex가 구조·원문 일치 여부를 확인한 것은 사람의 의미적 정답 검토와 다르다. 정답 완료 후
별도 평가 명령으로 항목 분류와 감성 분류를 계산하는 것이 다음 작업이다.
