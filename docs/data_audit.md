### 자동 번역 소량 시험

- 기존 로컬 모델: Ollama `qwen3.5:latest`, Q4_K_M, 9.7B, 로컬 크기 6.6GB
- 새 모델 다운로드: 없음
- 프롬프트 버전: `review-translation-ko-v1`
- 실제 DB 캐시 시험: 3건 성공, 0건 실패
- 처리 시간: 총 28.62초, 평균 9.54초/건(모델이 이미 로드된 CPU 실행)
- 5,224건 단순 환산: 약 13.8시간
- 자동 검사: JSON 구조, 빈 번역, 원문 숫자 누락 검사

3건 시험은 번역 파이프라인 동작 확인이며 번역 품질 검증 완료를 뜻하지 않는다. 부정어,
사용 기간, 고장·부작용 표현의 의미 보존은 카테고리별 사람 검토가 필요하다. 장시간 CPU를
사용하는 전체 번역은 소량 시험 결과를 보고한 뒤 별도 확인을 받아 실행한다.

기존 Appliances 상품 3개와 리뷰 7,801건은 삭제하지 않았다. 다만 공식 7개 카테고리의
`2개 × 7 = 14개`를 명확히 보이도록 기본 실제 목록에서 분리했다. fixture도 별도의
`source_mode=fixture`로 유지한다.

상품·기간에 대해 원천 식별 필드 전체가 같은 정확한 중복을 제거하므로 각각 373건이 됐다.
두 상품을 합친 원천 선택 행 8,096건 중 기간 밖 7,326건, 부적격 20건, 정확한 중복 4건을
제외해 746건을 저장했다. 문구가 같다는 이유만으로 다른 사용자의 리뷰를 제거하지 않았다.

제품 선정에는 감성이나 낮은 별점 비율을 사용하지 않았다. 3개월 합계가 목표 범위의 중앙인
375건에 가깝고 월별 편차가 과도하지 않은 후보 중, 서로 다른 제품 유형이 되도록 헤드폰과
보안 카메라를 골랐다. 선택 기간의 1~5점 리뷰를 모두 유지했다. `월 30건 이상`은 데이터
선정 조건일 뿐 통계적 충분성을 보장하지 않는다.

실제 Electronics 리뷰에는 분류 라벨을 넣지 않았다. 현재 화면과 비교 API는 월별 리뷰 수와
평균 별점만 제공하며 항목별 불만률은 `분석 전` 상태다. 기존 Appliances와 fixture는 삭제하거나
Electronics로 재표시하지 않았다.

동일 입력을 두 번째로 적재한 결과 `reviews_inserted=0`, `reviews_present=746`으로 중복 방지를
확인했다.

## 필드·형식 점검

리뷰 필드는 `rating`, `title`, `text`, `images`, `asin`, `parent_asin`, `user_id`, `timestamp`, `helpful_vote`, `verified_purchase`다. 메타데이터에는 상품명, 설명, 이미지, 카테고리, 집계 별점, `parent_asin` 등이 있다.

- timestamp는 Unix milliseconds이며 UTC로 변환했다.
- `asin`은 리뷰 대상 변형 상품, `parent_asin`은 상품군 연결 키로 사용했다.
- 표본과 전체 스캔에서 `asin != parent_asin`인 변형을 확인했다.
- 별점 1~5를 모두 유지했으며 높은 별점을 임의로 제외하지 않았다.
